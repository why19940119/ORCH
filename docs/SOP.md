# ORCH 標準作業程序（SOP，v0.21.0）

## 1. 每日運作

| 時間 | 負責人 | 工作 |
|---|---|---|
| 開工 | 管理員 | 打開 ORCH 總覽，確認沒有系統錯誤；伺服器可執行 `docker compose ps`（應顯示 healthy）。 |
| 開工 | 審批人 | 打開「審批收件箱」，先處理紅色「逾期」草稿。 |
| 日間 | 編輯 | 建立草稿，確認內容及資料來源後送審。 |
| 日間 | 審批人 | 在限期內批准或拒絕；拒絕必須寫原因。 |
| 收工 | 管理員 | 執行備份（見第 4 節），檢查「審計」頁當日記錄。 |

## 2. 審批流程

1. **編輯建立草稿** → 狀態「待審批」，自動計算限期。
2. **審批人審閱**：核對產品資料、價格、宣傳字眼、目標市場規例。
3. **決定**：
   - 批准 → 選擇發佈渠道 → 系統寫入不可變審計記錄（模擬發佈，不會對外發出）。
   - 拒絕 → 必須填寫原因 → 編輯可根據原因重新建立草稿。
4. **不可自我審批**：作者不能批准或拒絕自己的草稿（系統強制）。
5. **一次決定**：每份草稿只可決定一次；同時操作時系統只接受第一個決定。
6. **逾期處理**：草稿超過限期仍未決定，總覽及收件箱會顯示警告；管理員應聯絡審批人或重新指派模組審批人。

## 3. 帳戶管理

- 新增用戶、改變角色、停用、重設密碼：由管理員在「管理 → 用戶管理」提出，**另一名管理員批准**後生效（系統只有一名管理員時的例外情況會被記錄）。
- 員工離職：當日停用其帳戶；若該員是審批人，同時在「模組審批人」移除。
- 每月檢查一次權限清單（見第 5 節）。
- 帳戶被鎖定：確認是本人後，管理員在「用戶管理」按「解鎖」。

## 4. 備份、還原及升級

```bash
scripts/backup.sh                     # 每日；檔案在 backups/
scripts/restore.sh backups/<檔案>      # 還原（會先自動備份目前資料）
```

- 每日備份，至少保留 14 日，並複製一份到另一部機器或雲端儲存。
- 每月做一次還原演練（可在另一部機器）。
- 升級前必須先備份；升級時資料庫遷移會自動執行。
- 不要直接複製正在使用中的 `state/orch.db`；請使用 `scripts/backup.sh` 或 `python orch_db.py backup <目標檔>`。

## 5. 匯出權限清單（權限清單）

**網頁（建議）**

1. 以管理員登入。
2. 打開「管理 → 權限清單」（`/admin/permissions`）。
3. 按「匯出 CSV 檔」，下載 `orch-permissions-<日期>.csv`（UTF-8 BOM，可用 Excel 直接開啟）。
4. 清單包括每個帳戶的用戶名稱、角色、狀態及可審批的模組。
5. 每次匯出都會記錄在管治審計記錄（`permissions_exported`）。

**伺服器指令（備用）**

```bash
docker compose exec orch python orch_auth.py status
```

建議每月匯出一次，由另一名管理員核對後存檔。

## 6. 事故處理

| 情況 | 處理 |
|---|---|
| 網頁打不開 | `docker compose ps`、`docker compose logs --tail 100 orch`；必要時 `docker compose restart orch`。 |
| healthz 顯示 db error | 執行 `docker compose exec orch python orch_db.py check`；如非 `ok`，停機並用最近備份還原。 |
| 懷疑密碼外洩 | 立即停用帳戶，另一名管理員批准後重設密碼；檢查審計記錄中的登入紀錄。 |
| 誤批草稿 | 審計記錄不可修改；在審計頁記下 artifact 編號，由管理員書面記錄並通知相關人員（模擬發佈不會對外發出）。 |
