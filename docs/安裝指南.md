# ORCH 安裝指南（v0.21.0）

本指南說明如何在一部伺服器（或辦公室電腦）以 Docker 安裝 ORCH，以及不用 Docker 的本機安裝方法。

## 1. 系統需求

- Linux / macOS / Windows（WSL2），已安裝 Docker Engine 24+ 及 Docker Compose v2（`docker compose version`）
- 最少 1 GB 記憶體、2 GB 磁碟空間
- （選用）OpenRouter API 金鑰：沒有金鑰時，AI 草稿會使用示範（mock）內容

## 2. 取得程式

```bash
git clone https://github.com/why19940119/ORCH.git
cd ORCH
```

## 3. 設定 `.env`

```bash
cp .env.example .env
```

用文字編輯器打開 `.env`：

| 設定 | 說明 |
|---|---|
| `OPENROUTER_API_KEY` | OpenRouter 金鑰（選填）。只存在 `.env`，**不會**寫入映像檔。 |
| `OPENROUTER_VISION_MODEL` | 選填：處理「附有圖片」聊天的模型。預設 `mistralai/mistral-medium-3.1`（v0.21.1 起；舊預設 `google/gemini-2.0-flash-001` 已被 OpenRouter 停用）。留空時，如聊天模型（`OPENROUTER_MODEL`）支援圖片則沿用聊天模型。模型須支援圖片及 `response_format: json_object`。如日誌出現 HTTP 404「No endpoints found for …」，即該模型已停用，請改設現行模型並重新啟動。 |
| `ORCH_UI_SECRET_KEY` | 可留空。留空時，第一次啟動會自動產生並保存於資料卷 `state/secret_key`（權限 0600），重啟後登入狀態仍然有效。 |
| `ORCH_CLIENT_NAME` | 客戶／店舖名稱，顯示於頁首。 |
| `ORCH_LOGO` | 標誌：`https://` 網址，或 `state/` 內的檔案路徑（例如 `branding/logo.png`）。 |
| `ORCH_TARGET_MARKET` | 目標市場，例如「香港」。 |
| `ORCH_SETUP_TOKEN` | **設定權杖必填**（v0.21.1 起）：首次設定頁面 `/setup` 一律要求輸入設定權杖才可建立第一個管理員，不論是否對外開放（經隧道轉發時 Host 可能被改寫成 127.0.0.1，看似只在本機）。兩種方式擇一：在此設定 `ORCH_SETUP_TOKEN`（自訂權杖）；或留空，改用 ORCH 啟動時印在日誌／終端機的一次性權杖（`docker compose logs orch` 可見，搜尋「one-time token」；重啟後會換新）。未輸入正確權杖一律拒絕。 |
| `ORCH_SETUP_LOCAL_NO_TOKEN` | 只限本機開發：設為 `1` 時 `/setup` 不需權杖，啟動時會顯示警告。已設定 `ORCH_TRUSTED_HOSTS` 或 `ORCH_PROXY_FIX` 時此設定會被忽略。**正式部署切勿使用。** |

品牌設定亦可寫在資料卷內的 `state/branding.json`（環境變數優先）：

```json
{"client_name": "示範商店", "logo": "branding/logo.png", "target_market": "香港"}
```

## 4. 建置及啟動

```bash
docker compose up -d --build
docker compose ps          # STATUS 顯示 healthy 即成功
```

預設只在本機 `127.0.0.1:5050` 開放。要讓其他電腦連線，請在前面加上反向代理及 HTTPS，見 [反向代理與HTTPS.md](反向代理與HTTPS.md)。

## 5. 建立第一個管理員

用瀏覽器打開 `http://127.0.0.1:5050/setup`：

1. 輸入用戶名稱、密碼（10–128 個字元）及再次輸入密碼。
2. 輸入設定權杖：即 `.env` 內的 `ORCH_SETUP_TOKEN`；如未設定，請執行 `docker compose logs orch`，找出「one-time token: …」一行，複製該一次性權杖（重啟後會換一個新的）。
3. 按「建立管理員帳戶」，然後登入。

一旦有任何帳戶，`/setup` 會永久關閉。亦可用指令建立：

```bash
docker compose exec orch python orch_auth.py create-admin
```

之後到「管理 → 用戶管理」加入編輯（editor）及審批人（approver），並在「管理 → 模組審批人」指派各模組的審批人。

## 6. 資料存放位置（Docker 資料卷）

| 資料卷 | 內容 |
|---|---|
| `orch_state` → `/app/state` | `orch.db`（SQLite：任務狀態、審批、事件、帳戶、審計記錄）、`secret_key`、`branding.json`、`task_queue.json`（任務清單；第一次啟動時由映像檔內的預設清單複製，之後新增的任務會保留） |
| `orch_uploads` → `/app/uploads` | 聊天附件 |
| `orch_data` → `/app/data` | 匯入的 CSV（`data/import/`） |
| `orch_artifacts` → `/app/artifacts` | 不可變的草稿及審計 artifact |
| `orch_output` → `/app/output` | 任務執行產生的輸出檔 |

## 7. 備份及還原

```bash
scripts/backup.sh                       # 產生 backups/orch-backup-<時間>.tar.gz
scripts/restore.sh backups/orch-backup-<時間>.tar.gz
```

備份使用 SQLite 備份 API 取得一致的資料庫快照，應用程式運行中亦可備份。備份檔內含 `secret_key` 及帳戶密碼雜湊，因此權限固定為 0600（只有建立者可讀）；容器以非 root 用戶（uid 10001）執行，備份內容經標準輸出傳回主機寫入，不需要容器寫入主機的 `backups/` 資料夾（Linux 主機亦可直接使用）。還原前會先自動備份目前資料到 `backups/pre-restore/`；備份檔不完整時不會刪除任何現有資料。建議每日備份，並把備份檔複製到另一部機器（保持 0600 或加密保存）。

## 8. 升級

```bash
scripts/backup.sh                 # 先備份
git pull                          # 或取得新版映像檔
docker compose up -d --build      # 啟動時自動執行資料庫遷移
docker compose logs orch | tail   # 查看是否有遷移訊息
```

## 9. 由 v0.20.x（JSON 檔）升級

v0.21.0 會在第一次啟動時自動把 `state/*.json`、`state/*.jsonl` 匯入 `state/orch.db`，原檔移到 `state/json-backup-<UTC 時間>/`。**只會匯入空白的資料庫**：`orch.db` 已有資料時，`state/` 內再出現的 JSON 檔會被拒絕匯入（檔案保持原狀、不會刪除或覆蓋任何資料），並在日誌寫入 `REFUSED to import legacy JSON` 錯誤。確定要匯入時用 `python orch_db.py migrate --force`：會先備份成 `state/orch.db.pre-migrate-<UTC 時間>`（權限 0600），任務只更新/新增不刪除，記錄已存在的不會重複匯入。手動執行：

```bash
cp -a state state.pre-v0210-backup
python orch_db.py migrate
python orch_db.py status
```

還原到 v0.20.x：`python orch_db.py export /tmp/orch-json`，把匯出的檔案放回 `state/`，把 `state/orch.db*` 移走，再切換回舊版本。

## 10. 不用 Docker（本機）

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python serve.py          # http://127.0.0.1:5050
```

## 11. 健康檢查及煙霧測試

- `GET /healthz`：不需登入，只回傳版本及資料庫狀態。
- `scripts/smoke.sh`：建置 → 啟動 → 等待 healthz → 首次設定 → 登入 → 檢查主要頁面 → 清理。
- `scripts/smoke.sh --local`：不用 Docker 的同一套檢查。
